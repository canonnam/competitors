# Knowledge base navigation

`assets/navigation.js` enhances the existing pages without changing tool APIs or authentication. `assets/navigation.css` scopes the shared layout under `kb-navigable`.

- The `features` directory maps every home card to its route, category, concise description and search aliases. Add a matching entry when adding a home card. The directory is checked against the home links by `node --test test_navigation.cjs`.
- Desktop pages share a category sidebar. Ctrl/Cmd+K opens the native feature-search dialog; its former GNB button is removed. The home content begins with feature search, without a repeated site heading or introduction. Home category and search state survive a return through the URL.
- Favorites (including manually edited order) and the card/list preference are stored under `vida-navigation-v1` in this browser's localStorage. Layout version 2 defaults to the list, preserves existing favorites, and removes legacy recent-use history. Subsequent user selections of card view are remembered. These are device-local preferences; blocked storage falls back to in-memory state.
- Home cards retain their live status DOM nodes and IDs. Existing news, claim, advertising and monitoring collectors continue updating them; concise summaries keep every card the same height. Status summaries use a pale background and share an action row with the favorite tag, immediately to its left, in both card and list views. Filtering does not acknowledge unread news.
- `assets/news-badge.js` shares unread counts with category menus and feature search. Cached article IDs persist across navigation; detail pages fetch other feeds' summaries without marking them read. Only successfully displayed feed pages acknowledge their own articles. Fixed-size N badges do not shrink in mobile layouts.
- Seven monochrome Lucide line icons live in `assets/icons/line/`, matching the existing site icon library. `SOURCES.md` and `LICENSE` record the pinned source and ISC terms. SVG masks inherit the menu or favorite button color, so active states stay consistent. Icons appear in category menus and tag-shaped favorites controls; content titles and search results are text-only, apart from unread N badges. The previous Icons8 footer credit is removed because the interface no longer uses those images.
- Menus and cards use a light gray hover background. Feature title padding explicitly overrides the legacy claim card spacing, keeping its title and description aligned with other cards in both views.
- `support-share.html` is intentionally excluded from internal navigation. Its expiring, scoped external share flow remains unchanged.

Validation: navigation/storage/search and unread-feed tests; all 17 internal pages mounted against their actual HTML with live status node identity preserved; browser checks at 320px and 390px mobile widths and desktop card view, including equal heights, intact N badges, and unread menu counts clearing after reading a feed. The existing metadata suite already fails for missing `og:url` on `support-projects.html` and `support-share.html`; navigation does not modify their sharing metadata.

Fluency update verified in the browser: identical payroll/claim/operating-cost title offsets in desktop list and card views, consistent title offsets across all 14 mobile rows at 320px, no clipped content or horizontal overflow, loaded icon assets, and `rgb(240, 241, 243)` hover backgrounds for both a menu and a card.

Line-icon update verified in desktop and 320px mobile views: all seven 20px SVG icons render, active menu and tag colors inherit correctly, content titles remain icon-free, N badges keep their 18px square dimensions, and the obsolete Icons8 credit is absent.

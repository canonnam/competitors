# 홈페이지 상담·무료체험 접수

홈 카드 **상담·무료체험 신청** → `/website-requests.html`에서 방문상담, 무료체험, 비용 문의를 관리합니다. 별도 담당자 접근 키 없이 목록·신청 상세·처리 상태·메모를 조회하고 관리합니다. 대시보드에는 집계만 표시하고 연락처나 접수 내용은 신청 관리 화면에서 확인합니다.

신청은 최신 접수순의 게시판 목록으로 표시합니다. 신청 제목이나 행을 누르면 우측에서 상세 내용·연락처·처리 상태·담당자 메모를 확인하고 저장합니다. 모바일에서는 상세 화면의 ‘목록으로’ 버튼으로 돌아갑니다. 작성 중인 상태와 메모는 다른 신청이나 페이지를 조회해도 현재 브라우저 화면에서 유지하며, 화면을 닫으면 지웁니다. 서버에 반영하려면 ‘상태·메모 저장’을 눌러야 합니다.

- `POST /api/website-intake`: 서버 간 접수 전용. `WEBSITE_INTAKE_SECRET` Bearer 인증. 접수 생성용 비밀 키는 서버에서만 사용합니다.
- `GET /api/support/website-requests`: 별도 접근 키 불필요. 유형·상태·개발/운영 사이트 필터, 30건 단위 페이지.
- `GET /api/support/website-requests/summary`: 별도 접근 키 불필요. 대시보드용 운영 사이트 상태별·유형별 건수와 최근 접수/조회 시각만 반환한다. 개발 사이트는 제외하고 신청자·연락처·메모는 반환하지 않는다. 응답은 no-store. 홈은 집계만 표시하고 숨김·조회 실패 시 집계를 지운다.
- `POST /api/support/website-requests/status`: 별도 접근 키 불필요, 동일 출처 검증 유지. 새 접수/상담 중/상담 완료/보관함, 담당자 메모.
- `WEBSITE_INTAKE_DB_PATH` 기본 `/data/website-intake.db`. Railway의 기존 영구 볼륨 사용. 배포 시 유지.
- 접수 ID는 UUID이며 동일 ID 재시도는 기존 접수를 반환합니다. 동일 ID의 내용 변경은 거부합니다. 익명화된 발신자 식별값당 10분에 5건으로 제한합니다.
- 요청 본문 최대 16KB, 수집 동의·입력 형식 검증. 신청 내용은 로그·공개 정적 파일·AI 지식 검색에 포함하지 않습니다.
- 테스트: `python -m unittest test_website_intake -v`. 임시 DB와 로컬 서버만 사용합니다.

운영에서 정한 개인정보 보유 기간이 끝나면 별도 승인된 파기 절차를 적용해야 합니다. 보관함은 복구 가능한 상태 변경이며 영구 파기가 아닙니다.

## 텔레그램 새 신청 알림

- `website_telegram.py`가 새 접수와 같은 SQLite 트랜잭션에 전송 대기 항목을 저장한다. 서버의 별도 작업자가 5초마다 대기 항목을 처리하므로 텔레그램 응답을 기다리느라 상담 접수가 지연되지 않는다. 같은 접수 ID의 재요청·처리 상태 변경에는 알림을 추가하지 않는다.
- Railway `competitors/dev` 서비스의 서버 비밀 변수 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`를 설정한다. 수신자는 먼저 봇의 개인 채팅을 시작해야 하며, 연결 메시지로 확인한 개인 채팅 ID만 사용한다. 토큰·개인 채팅 ID의 실제 값은 Git·HTML·로그·문서에 남기지 않는다.
- `WEBSITE_TELEGRAM_ENABLED=true`가 기본값이며 토큰과 개인 채팅 ID가 모두 설정돼야 작동한다. `WEBSITE_TELEGRAM_NOTIFY_DEV=false`가 기본값으로 production 접수만 알린다. 개발 접수를 함께 받으려면 이 값을 `true`로 설정하며 알림에 개발 사이트 표시가 붙는다.
- 알림에 신청 유형·한국 시간·신청자 또는 보호자·연락처·기관명 또는 희망 지점/방문일시·문의 내용과 접수번호를 표시한다. 긴 문의는 알림에서 줄이고 원문은 기존 상담함에 보존한다. 상담함 열기 버튼은 기존 비밀번호 인증이 필요한 페이지로 연결된다. 봇 알림은 일반 텍스트이며 링크 미리보기와 전달·저장을 제한한다.
- `website_telegram_outbox`는 기존 `/data/website-intake.db`에 생성한다. 활성화 이전 접수는 소급 전송하지 않는다. 실패는 개인정보 없는 오류 코드만 저장하며 30초부터 최대 1시간 간격으로 재시도하고 Telegram의 `retry_after`를 따른다. 서버 재시작 뒤에도 전송 대기 상태를 유지하며, 작업자가 중단된 항목은 120초 잠금이 만료된 뒤 다시 처리한다.
- 전송 완료와 동일 접수의 중복 등록은 재전송하지 않는다. 다만 Telegram이 메시지를 받은 직후 응답이 유실되거나 완료 기록 전에 서버가 중단되면 재시도 메시지가 중복될 수 있다. 같은 접수번호로 식별한다. 수신 채팅 ID를 변경하면 이전 채팅용 대기 항목을 새 채팅으로 전달하지 않는다.
- 테스트: `python -m unittest test_website_telegram test_website_intake`. 합성 접수·임시 DB·모의 Telegram 응답을 사용한다. 실제 연결 시험은 개인정보 없는 테스트 알림으로 확인한다.

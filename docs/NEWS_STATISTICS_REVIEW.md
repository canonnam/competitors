# 두 수집 뉴스의 연구·조사·통계 검토 절차

사용자 요청(2026-11-17, 11-18 이어서 처리): 경쟁사 및 요양원 뉴스와 기관 뉴스에 수집된 새 연구·공식 조사·통계자료를 발행기관 원문과 대조하고, 검증한 자료를 기존 통계자료 화면에 반영한다.

## 기존 점검에 연결

- 기존 자동화 감시·복구 점검에서 두 뉴스의 당일 수집 상태를 확인한 다음 수행한다. 별도 뉴스 수집기나 중복 예약을 만들지 않는다. 두 뉴스의 수집 성공과 이 원문 검토의 완료를 구분한다.
- 운영의 `/api/competitor-news`, `/api/agency-news`를 기존 로그인 또는 인증된 Railway 읽기 경로로 조회한다. 마지막 검토 기준 시각부터 이번 시각까지 `first_seen_at`, `collected_at`, `updated_at`을 비교한다. 날짜만 있으면 한국 시간으로 해석한다.
- 마지막 기준일 하루 전부터 겹쳐 읽고 기사 ID·원문 문서 ID로 중복을 제거한다. N은 자정에 사라지므로 N이 있는 글만 검토하지 않는다. 며칠 건너뛴 경우 마지막 완료 구간부터 누락 없이 읽는다.
- 수집처별 실패·지연이면 정상 수집된 범위와 미검토 범위를 나누어 기록한다. 미완료 범위와 기존 보류 후보는 다음 실행에 넘긴다. 검토일을 수집 성공일로 대신하지 않는다.

## 원문 확인과 판정

1. 연구, 보고서, 조사, 통계, 실태, 분석 등 제목뿐 아니라 본문의 인용 자료를 확인한다. 장기요양·요양시설 운영, 인력, 이용자·가족, 비용·품질·안전과 관련된 공식 발간물을 후보로 삼는다. 신규 설문 모집·협약·시범사업 계획·제도 시행 보도는 결과 통계와 구분한다.
2. 기사에서 발행기관의 공식 자료 페이지·PDF·공개 데이터·도서관 원문으로 이동한다. 제목·저자·발행기관·발행일·문서 ID 또는 DOI를 기록한다. 보도일, 사이트 최초 수집일, 원문 발행일, 조사·분석 기간을 따로 적는다.
3. 기존 `assets/statistics-data.js`, `data/statistics_sources.json`, `STATISTICS_LIBRARY.md`에서 문서 ID·원문 주소·제목/기관/발행일을 대조한다. 같은 연구를 인용한 다른 기사는 새 문서로 추가하지 않는다. 개정판이라면 변경 범위와 원문 해시를 확인한다.
4. 방법·표·주석을 읽고 조사 대상, 지역, 표본/분모, 단위, 가중치, 기간과 표 번호·본문 쪽·PDF 실제 페이지를 확인한다. 관측치와 인원, 급여비와 실부담액, 의료 이용과 질환 발생률을 구분한다. 추정 효과를 개별 시설 실적으로 바꾸지 않는다.
5. 원문이 없거나 표·분모를 확인하지 못하면 통계자료에 새 수치를 게시하지 않는다. 기사 URL·수집 ID, 검색한 기관/저장소, 보류 사유와 다음 확인 경로를 해당 날짜 MD에 기록한다. 다음 실행에서 보류 목록도 재확인한다. 기존의 별도 '기사 인용 통계'를 확인된 공식 원문으로 승격하지 않는다.

## 반영과 검증

- 검증된 자료만 기존 자료/책갈피 구조로 추가한다. 해석과 더비다의 활용 아이디어를 구분하고, 자료별 대상·기간과 주의점을 표시한다.
- 원문 PDF는 `.local/statistics/`에 보관한다. `data/statistics_sources.json`에 SHA-256·PDF 페이지 수·발췌 좌표를 기록한다. 전체 원문을 Git·배포 이미지에 넣지 않는다.
- `python scripts/build_statistics_captures.py --document 문서ID`로 캡처를 만들고 전체 해당 페이지와 발췌 이미지의 표 제목·열·단위·주석을 눈으로 대조한다.
- `assets/statistics-data.js`, 정적 화면의 자료 수·확인일과 `STATISTICS_LIBRARY.md`를 갱신하고 `node scripts/build_service_catalogs.cjs`로 질문 검색용 자료를 다시 만든다. `data/card_updates.json`에는 실제 반영 시각을 기록한다.
- `node --test test_statistics.cjs`, `node scripts/build_service_catalogs.cjs --check`, `python -m unittest test_ui_consistency.py test_static_pages.py test_card_knowledge.py`와 변경 범위에 맞는 기존 검사를 실행한다.
- 원격 petdev의 최신 변경을 보존해 기존 Railway 흐름으로 배포한다. 배포 성공, 실행 파일·캡처 해시와 운영 화면의 검색·자료 수·책갈피·확대/원문 링크를 확인한다. 로그인 불가 등 화면 확인의 한계가 있으면 실제 확인 범위와 함께 남긴다.

# 실제 네이버·AI 웹 검색 점검

검색노출 현황은 네이버·ChatGPT·Gemini 모두 Computer Use로 확인한 **실제 웹 화면** 결과를 표시한다.
2026-09-21 사용자 요청에 따라 네이버 서버 HTTP 수집을 중단하고 브라우저 관측으로 전환했다.
과거 서버 관측은 날짜와 함께 보존하며, 현재 정상 집계에는 브라우저 관측만 포함한다.
검색노출 기능의 OpenAI·Gemini·Perplexity 추론 API 호출 및 정기 수집은 제거했다.
다른 기능에서 사용 중인 API 연결은 변경하지 않는다. 기존 API 관측 DB는 보존하되
웹 집계·답변·관측 기록에 포함하지 않는다. 기존 AEO 미션은 provider 별칭으로 진행 기록을 유지한다.

## 월·수·금 점검 절차

Codex의 이 작업에 연결된 heartbeat가 매주 월·수·금 10:50 Asia/Seoul에 실행한다.
API `GET https://app.aivida.tech/api/search-visibility`의 `ai_queries`를 읽고
각 질문을 `chatgpt_web`, `gemini_web` 두 서비스에서 그대로 검색한다.
현재 인천 3개, 안양 3개로 총 12개 웹 답변이다. 질문마다 새 대화를 시작한다.
기존에 같은 정기 점검 시점 이후 정상 관측이 있으면 중복 질의를 생략한다.

- Computer Use로 실제 `https://chatgpt.com/`, `https://gemini.google.com/app`에 접속한다.
- 브랜드명·숨은 지시·API용 프롬프트를 질문에 추가하지 않는다.
- 로그아웃 상태로 가능한 경우 그 상태를 일관되게 사용한다. 로그인된 환경이면
  그 사실을 기록한다. 계정 설정이나 정밀 위치 권한을 임의로 변경하지 않는다.
- 검색이 필요한 지역 추천 질문을 제출한다. 실제 검색 출처나 지도·장소 카드가
  나타났는지 확인한다. 생성 중인 텍스트나 검색하지 않은 일반 답변은 성공으로 저장하지 않는다.
- 생성 완료된 답변 본문 및 표시된 장소 카드의 이름·지역을 원문 그대로 기록한다.
  출처 패널의 URL, 실제 대화 URL, 화면에서 확인한 모드, 확인 시각, 검색 환경을 함께 남긴다.
  모델 이름이 표시되지 않았다면 추측하지 않는다.
- 이미 있는 대화에 후속 질문을 이어 붙이거나 브랜드 노출을 유도하지 않는다.
- 접근 제한, 로그인 필요, 보안 확인, 사용량 제한, 브라우저 실패는 `blocked`와
  구체적인 사유로 기록한다. 확인하지 못한 답변을 미언급으로 쓰지 않는다.
- 보안 확인을 우회하지 않는다. 완료하지 않은 미션을 체크하지 않는다.

## 네이버 Computer Use 점검

같은 GET 응답의 `providers`에서 `id: naver`의 `items[].query`를 읽는다.
인천은 광고 계정 ON 키워드만, 안양은 활성화된 지역 점검 키워드만 점검한다.
현재 19개이지만 개수를 고정하지 않는다. OFF 키워드를 이전 목록에서 복원하지 않는다.
`keyword_source.stale`이면 광고 키워드의 ON 상태를 확정하지 말고 목록 갱신 실패를 기록한다.

- 실제 네이버 검색 화면에서 등록 키워드 그대로 검색한다. `search.naver.com/search.naver?where=nexearch&query=...`로 접속할 수 있다.
- 기존 로그인 상태를 유지하고 `session_context`에 로그인 여부와 기본 위치 사용 여부를 기록한다. 자동 로그아웃, 쿠키 추출, 계정·위치 설정 변경을 하지 않는다.
- 실제 화면의 페이지 링크로 1페이지부터 GET의 `max_pages`까지 확인한다. 다음 페이지가 실제로 없으면 거기서 종료한다. 페이지 주소의 검색어가 바뀌거나 필수 범위를 확인하지 못하면 blocked 사유로 기록한다.
- 각 페이지의 검색 결과 본문을 원문으로 캡처한다. 계정 헤더·개인 알림·메일·프로필은 제외한다. DOM은 화면에 표시된 검색 결과를 읽는 용도로만 사용하고 숨은 API나 서버 HTTP 수집으로 대체하지 않는다.
- `results`에는 화면에 실제로 나타난 더비다 브랜드 또는 공식 주소 항목을 모두 기록한다. 다른 업체 전체를 저장할 필요는 없지만 `position`은 해당 영역 전체 목록에서 세는 순서이다.
- 영역은 자연검색 문서 `web`(블로그·카페 포함), 자연검색 장소 `place`, 파워링크 `ad`, 장소 광고 `place_ad`로 나눈다. 광고를 클릭하지 않고 표시된 링크만 읽는다. 광고는 자연검색 노출 분자에서 제외된다.
- 전체 목록에서 더비다·공식 주소가 없을 때만 `results: []`를 쓴다. 본문·주소·제목을 페이지별 독립 객체에 바로 보관한다.
- 동일 due_at 이후 정상 브라우저 기록이 있으면 중복 검색하지 않는다. 이전 서버 HTTP 403 기록은 현재 PC의 접근 실패로 재사용하지 않는다.
- 실제 PC에서 CAPTCHA·접근 제한이 보이면 해당 요청을 멈춘다. 남은 항목도 동일 제한으로 진행하지 못한 구체적 사유를 각각 저장한다. 보안 확인 우회, IP·프록시 교체, 탐지 회피를 하지 않는다.

네이버는 대시보드 WebMCP `record_naver_web_observation`을 사용한다. 내부 대체 저장 경로는 AI와 같은 `POST /api/search-visibility/web-results`이며 형식은 다음과 같다.

```json
{
  "provider": "naver",
  "keyword": "등록 키워드 그대로",
  "branch": "incheon",
  "request_id": "새 UUID",
  "observed_at": "시간대가 포함된 실제 확인 시각",
  "status": "ready",
  "capture_method": "browser",
  "session_context": "기존 로그인 상태 · 브라우저 기본 위치",
  "complete_search": true,
  "pages": [{
    "page": 1,
    "url": "실제 해당 키워드·페이지의 네이버 검색 URL",
    "text": "개인 영역을 제외한 검색 결과 본문 전체",
    "has_next": false,
    "results": [{"area": "web", "position": 3, "title": "실제 결과 제목", "url": "실제 결과 링크", "snippet": "실제 설명"}]
  }]
}
```

위 예시는 형식 설명용이며 실측값으로 대체해야 한다. `has_next`는 실제 화면 기준으로 기록한다.
`max_pages` 전 다음 페이지가 남아 있으면 정상 저장이 거절된다. 실패는 `status: blocked`,
`reason`, 실제 시도 시각과 검색 환경을 보내고 `pages: []`로 기록한다.
저장한 전체 `pages[].text`, 페이지 URL, `results` 제목·주소·영역·순서를 GET 응답과 비교한다.
실패 기록은 `last_attempt_request_id`, `last_attempt`, `error`로 확인한다.
이번 due_at 이후 모든 네이버 항목에도 정상 결과 또는 구체적인 실패 기록이 있어야 정기 실행이 완료된다.

## 저장

대시보드 페이지의 WebMCP `record_web_search_observation`을 사용하면
브라우저에서 수집한 문자열을 그대로 저장할 수 있다. 지원되지 않는 환경에서는
화면에서 읽은 동일 내용을 JSON 파일에 저장한 뒤 아래 내부 서비스 경로로 제출한다.
이는 관측 기록 저장이며 AI 추론 호출이 아니다.

`POST https://app.aivida.tech/api/search-visibility/web-results`, JSON 형식:

```json
{
  "provider": "chatgpt_web",
  "keyword": "인천 요양원 추천",
  "branch": "incheon",
  "request_id": "새 UUID",
  "observed_at": "시간대가 포함된 실제 확인 시각",
  "status": "ready",
  "capture_method": "browser",
  "session_context": "비로그인 · 새 대화 · 브라우저 기본 위치",
  "model": "화면에 표시된 모드 또는 모델명 미표시",
  "answer": "직접 확인한 전체 웹 답변 및 표시된 장소 카드 내용",
  "search_confirmed": true,
  "complete_answer": true,
  "surfaces": ["answer", "places"],
  "conversation_url": "실제 관측한 웹 대화 주소",
  "sources": [{"title": "표시된 출처 제목", "url": "실제 출처 주소"}]
}
```

장소 카드가 없었으면 `surfaces`는 `['answer']`만 사용한다. 검색 출처가 확인되면
카드가 없어도 정상 관측이다. 공유 링크 생성은 필수가 아니다. 실패일 때는
`status: blocked`, 실제 시도 시각, `reason`, `surfaces: ['answer']`를 보내고
답변·검색 확인 항목은 비워 둔다. 실패 요청에 답변을 넣어도 서버는 저장하지 않는다.
재시도는 같은 내용과 같은 request_id를 사용하여 중복 저장을 방지한다.

저장 후 운영 GET 응답에서 provider·keyword·branch·request_id·observed_at을
대조한다. 각 질문을 독립 객체로 보관하고 저장한 `answer` 전체 본문과 `citations`의
주소·제목도 원본과 비교한다. 다른 질문의 본문이 복제되면 정상 처리하지 않는다.
종료 전 이번 `due_at` 이후 정상 결과 또는 구체적인 실패 기록이 모든 질문·서비스에
존재하는지 확인한다. 이번 점검이 누락된 항목을 다음 점검일만 안내하고 종료하지 않는다.
실패 기록은 `last_attempt`, `error`로 확인한다. 서버는 마지막 정상 답변과
확인 시각을 유지하며, 실패 또는 오래된 결과는 현재 분모에서 제외한다.
쿠키·로그인 토큰·브라우저 프로필·개인 대화·비밀번호는 저장하거나 전송하지 않는다.

이전 정상 결과와 의미 있는 노출 변화, 실행 실패, 사용자 조치가 필요한 경우에만
사용자에게 알린다. 변화가 없는 정상 정기 점검은 조용히 종료한다.

## 첫 액션

인천점·안양점 각각 고객용 공개 안내 페이지 한 개를 정비한다. 시설명, 주소,
연락처, 입소 대상, 실제 서비스, 상담 방법을 본문 글자로 제공하고 보호자 질문
3개와 정보 확인일을 추가한다. 로그인 없이 열리고 검색봇 접근과 색인이
차단되지 않는지 확인한 뒤 해당 URL과 점검 결과를 미션에 기록한다.
내부 지식 창고를 검색엔진에 공개하는 작업은 아니다.

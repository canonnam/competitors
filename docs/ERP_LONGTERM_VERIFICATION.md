# ERP와 롱텀보고 월별 검증

## 일정과 업무 범위

매월 9일 09:00 한국시간에 Codex의 현재 운영분석 채팅에서 안양점과 인천점의 전월 급여제공 자료를 확인한다. 1월 실행은 전년도 12월을 확인한다. 이 점검은 지점별 청구 접수·인건비 비율을 조회하는 기존 일정과 별도다.

- 작업 폴더의 `dongsan-silvercare/BILLING_WORKFLOW.md`와 `HISTORY.md`를 보고 Windows의 기존 설치본에서 **실제 자료 조회·비교**를 사용한다. 로컬 업무 포트는 4317이다. 같은 기관의 다른 실행이나 미저장 입력 창이 열려 있으면 해당 작업 상태를 확인한다.
- 등록된 케어포 기관과 공단 로그인 기관, 열린 업무 창의 급여제공년월이 지점과 일치하는지 확인한다. 공단 세션이 없거나 기관이 다르면 담당자의 공동인증서 로그인 뒤 그 지점 점검을 이어간다.
- **입퇴소·외박, 근무내용, 기타자료, 프로그램** 네 업무를 확인한다. 프로그램은 제목·강사·일정까지 확인한다. 조회에서 확인한 기록 차이와 자료 확인이 필요한 항목을 기록한다. 결정요청, 수정, 업로드, 저장, 제출과 최종 청구 전송은 담당자 업무다.
- 일부 조회가 중단되면 확인한 범위와 원인을 적는다. 같은 지점·급여제공월의 검증이 끝나면 기존 자료와 대조해 월별 결과를 갱신한다. 두 지점의 원본은 기존 Windows 보호 저장소와 로컬 작업 폴더에서 사용한다.

## 지식 창고 반영

- 집계와 상세는 Railway 비공개 볼륨에서 관리한다. `months[YYYY-MM][지점]`의 지점 키는 `anyang`, `incheon`이다. 네 업무를 확인했으면 `complete`, 일부만 확인했으면 `partial`, 조회가 막혔으면 `blocked`를 기록하고 사유를 `note`에 적는다.
- `findings`에는 `month`, `branch`, `category`, `type`, `detail`을 적는다. 업무 값은 `admission`, `work`, `misc`, `program`이며 구분은 `difference` 또는 `review`다. 확인한 일자와 공개 가능한 프로그램명·자료 유형은 선택 값인 `date`, `subject`에 적는다. 사람의 이름, 생년월일, 개인 식별정보, 계정, 원본 파일은 게시 자료와 변경 기록에서 제외한다.
- 동일 지점·월을 재점검하면 해당 지점·월의 최신 건별 결과를 모두 담는다. 실제로 개선하거나 재검증한 내용은 `updates`에 `date`, `title`, `detail`로 추가하고 `updatedOn`에 반영일을 적는다. 오류가 발생해도 이미 완료된 지점·월의 결과를 유지한다.
- 변경할 지점·월만 담은 JSON을 `.local/`에 저장한다. `python -X utf8 scripts/publish_erp_longterm_verification.py .local/검증결과.json`으로 형식과 건수를 확인한 뒤 `--publish`를 붙여 게시한다. 게시기는 기존 Railway 연결에서 월·지점별로 병합하고 저장 전후 자료의 해시를 대조한다. 웹 화면의 N 표시는 실제 게시 시각을 사용한다.
- 기존 점검 월과 다른 지점의 자료가 보존되고 집계와 건별 내역이 일치하는지 확인한다. `docs/CHANGELOG.md`에 근거와 검증 내용을 남긴다. 운영 사이트 반영 확인 후 이 채팅에 지점별 점검 상태와 사이트 링크를 남긴다.

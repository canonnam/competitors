# 평판 점검의 규칙 기반 선별

2026-11-18 사용자 요청으로 평판 분류를 기존 Railway 서버 내부 규칙으로 전환했다. 별도 유료 API 키·추가 서비스·PC 가동은 필요하지 않다. 수집은 기존 공개 네이버 검색·Google 뉴스 피드와 매일 09:30 KST 일정을 사용한다.

## 판정 기준

- 수집한 제목·요약의 연속된 표현만 근거로 사용한다. 지점은 인천·미추홀·숭의동 또는 안양·만안구·명학역 등의 표기에서 확인한다. 지점 미표기와 대상 미확인을 구분한다.
- 돌봄·안전, 직원·응대, 비용·계약, 시설·위생, 행정·운영의 주의 표현을 선별한다. 같은 문장에 브랜드와 구체적 피해·불만 주장이 명시된 경우 부정적 언급 후보로 표시한다. 주장 내용의 사실 여부는 원문 확인 대상이다.
- 질문·일반 업계 문제·다른 시설의 주장·대상이나 문맥 미확정은 확인 대기로 남긴다. AI 생성 요약 안내가 섞였거나 제목·요약의 정보가 부족한 경우도 원문 확인 대상이다.
- 예방·방지교육, 부정 표현의 명시적 부정·0건 표기는 해당 표현만 제외한다. 같은 문장의 다른 주의 표현은 계속 검토한다. 부정 표현이 없는 시설 안내·채용·예방교육·긍정 평가 문구는 부정 표현 미감지로 표시한다.
- 다른 지역의 동명 지점으로 명시된 경우 무관으로 표시한다. 그 밖의 판단 근거 부족은 확인 대기로 남긴다.

## 저장과 실행

- 기존 URL 정규화·문서 ID·중복 병합·SQLite를 사용한다. 분류 버전과 제목·요약이 같은 자료는 다시 선별하지 않는다. 규칙 버전은 `reputation-rules-1`이다.
- 버전이 달라진 첫 실행은 이전 OpenAI 인증 실패의 호출 한도를 승계하지 않는다. 새 버전 안에서는 기존 배치·중복 방지·실패 재시도 간격을 유지한다. 과거 분류 행과 전체 완료 이력을 삭제하지 않는다.
- 당일 정상 수집처에서 얻은 최신 문서만 현재 분류 대상으로 삼는다. 실패 출처의 과거 캐시·이전 감지 근거는 보존하며 당일 수집으로 세지 않는다.
- 수집 실패는 출처별 상태, 분류 실패는 analysis 상태로 구분한다. 전체 수집처와 자동 선별이 완료돼야 전체 완료 이력을 추가한다. 원문 확인 대기 건수는 자동 선별 대기 건수와 별도로 표시한다.
- 공용 `OPENAI_API_KEY`와 다른 기능의 모델·설정을 변경하지 않는다. 평판 코드의 외부 추론 API 호출과 `REPUTATION_MODEL` 의존성을 제거했다.

## 검증

Python 평판·정적 화면·공통 UI 검사와 Node 평판 표시 검사를 실행한다. 운영 저장본 재현 검증에서는 키를 비우고 외부 추론 호출을 금지한 상태로 처리한 뒤 재실행 중복 방지, 이전 분류·이력과 수집처 상태 보존을 대조한다. 실제 운영 반영 결과는 날짜별 이력에 기록한다.

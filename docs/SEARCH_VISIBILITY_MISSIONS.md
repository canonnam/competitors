# 검색노출 ON 키워드와 AEO 미션

검색 수집·상세 화면·홈 집계는 동일한 ON 키워드 목록을 사용한다. 캠페인,
광고그룹, 키워드의 ON 상태를 저장하며 집행 가능 상태(`eligible`)와 구분한다.
ON 상태 필드가 없는 기존 스냅샷은 집행 가능 항목만 사용한다. 목록 갱신 실패 시에도
OFF 항목을 다시 포함하지 않는다. 중복 키워드는 ON 항목의 그룹과 순위만 사용한다.
안양 지역 점검 키워드는 광고 계정 항목과 구분하며 `enabled: false`로 제외할 수 있다.
ON/OFF 반영 시점은 기존 광고 목록의 일일 갱신 시점이다.

AI 질문 카드에는 현재 미션 한 개와 전체 순서·진행 기록을 표시한다.

- 정상 관측에서 해당 지점 미언급: 공개 페이지 → 지점 정보 → 질문별 안내 글 → 근거 연결 → 7일 비교.
- 해당 지점 언급: 기존 출처 점검 → 연관 질문 보완 → 근거 연결 → 7일 비교.
- 미연결·오류·오래된 관측·지점 미확인: 측정·지점 확인 후 개선 순서.

AI의 고정 순위는 측정하지 않는다. 단계 완료는 사용자의 작업 완료 기록이며,
관측의 언급·인용 결과를 수정하지 않는다. 안내는 공식 검색 가이드에 기반한
규칙별 제안으로, 미션 조회·제출에 추가 AI 요청은 없다.

`POST /api/search-visibility/missions`는 현재 등록된 AI 질문의 현재 단계만 변경한다.
완료는 다음 단계로 이동하고, 미완료는 사유 종류와 구체적인 이유를 필수로 받는다.
미완료는 현재 단계를 유지하고 권한·자료·시간 등의 사유에 맞는 재시도 안내를 붙인다.
메모와 결과 URL은 선택 입력이다. 입력 중 자동 갱신은 폼을 교체하지 않는다.

상태는 기존 `SEARCH_VISIBILITY_DB_PATH`의 `aeo_plans`, `aeo_events`에 추가 저장한다.
지점·서비스·질문별 공유 진행 기록이며 첫 제출 이후 계획 순서를 고정한다.
재시작과 일별 관측 변경으로 완료 기록이 사라지지 않는다. SQLite 트랜잭션,
리비전 검사와 요청 UUID로 동시 제출·네트워크 재시도가 두 단계를 진행하지 않도록 한다.
기존 동일 출처 JSON 제출 방식과 정적 파일 공개 범위를 유지한다.

검증: `python -m unittest test_aeo_missions test_search_visibility test_naver_keywords test_static_pages`
및 `node --test test_aeo_missions.cjs test_search_visibility.cjs test_naver_keywords.cjs`.

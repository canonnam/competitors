# 더비다 지식창고 UI·UX 규칙

이 문서는 내부 업무 화면의 공통 기준이다. UI 변경 전 읽고, 새 화면과 기존 화면 수정에 동일하게 적용한다. 사용자의 최신 요청이 기준을 바꾸면 해당 구현과 이 문서를 함께 갱신한다.

## 기준 파일과 우선순위

1. 사용자의 최신 명시적 요구
2. 이 문서의 확정된 디자인·동작 규칙
3. `assets/ui-foundation.css`의 공통 토큰·컴포넌트
4. `assets/site.css`의 공통 헤더·상세 제목
5. `assets/navigation.css`, `assets/navigation.js`의 탐색 기능
6. 개별 기능의 레이아웃·데이터 표시

모든 내부 HTML은 공통 foundation 스타일을 한 번, 마지막 스타일시트로 불러온다. 페이지 CSS에 공통 버튼·색상·포커스 규칙을 다시 만들지 않는다. 추가 기능은 기존 구성요소를 재사용하고, 필요한 공통 변경은 foundation에서 처리한다. 범위가 좁은 업무별 예외는 클래스와 이유를 명시한다.

## 확정된 홈·탐색 규칙

- 상단 핵심 현황은 미확인 새 소식·추천 지원사업·검색노출 현황·광고 평균 3위 이내로 구성한다. 검색노출 카드는 네이버 첫 페이지 노출 수 / 이번 점검 완료 키워드 수(광고 제외)를 표시하고 전체 대상 중 점검 완료 수도 함께 안내한다. 미측정·오류·이전 관측은 현재 노출 0건으로 해석하지 않는다. 클릭하면 검색노출 상세로 이동하며 청구 접수 정보는 지점별 상태표에서 유지한다.
- 홈의 기본 보기는 대시보드이며 본문은 제목과 맨 오른쪽 날짜로 시작한다. 대시보드에는 기능 검색창, ‘전체 기능 보기’ 버튼, ‘오늘 확인할 소식과 업무’ 부제목을 표시하지 않는다. 왼쪽·모바일 메뉴에서 대시보드, 전체 기능, 카테고리를 전환하며 모바일 메뉴는 대시보드에서도 유지한다. 전체 기능·카테고리 화면의 기능 검색과 Ctrl/Cmd+K 검색은 유지한다. 큰 사이트 소개와 최근 사용 영역은 추가하지 않는다.
- 대시보드는 핵심 현황·지점별 상태표·상담·무료체험 신청 현황·광고 추이·운영비 분석을 요약한다. ‘확인할 항목’, 독립적인 ‘지점별 청구’, ‘시장·정책 새 소식’, ‘마케팅·점검 현황’ 카드는 표시하지 않는다. 상단 미확인 새 소식은 뉴스 기능 검색으로 연결한다. 수집 시각, 로딩, 오류, 이전 결과를 구분하고 미조회 값을 0으로 표시하지 않는다. 미확인 글은 브라우저 읽음 기록 기준이며 대시보드 진입만으로 읽음 처리하지 않는다.
- 대시보드 운영비 분석은 지점별 성과 카드 대신 월별 운영손익 묶음 막대그래프를 상단 핵심 현황 카드 4개 바로 아래, 지점별 상태표·상담 현황 위에 배치한다. 그래프 위에 공통 입력 스타일을 따르는 지점 선택 상자를 두고 ‘전체 지점’(기본값), ‘안양점’, ‘인천점’ 중 하나를 고를 수 있게 한다. 전체 지점 보기에서는 등록된 최신 연도의 두 지점을 함께, 한 지점을 고르면 해당 지점만 표시하며 범례와 그래프의 접근성 이름도 선택에 맞춘다. 손익은 만원 단위의 같은 축에서 비교하고 0 기준선 위·아래로 흑자·적자를 구분한다. 최신 월 막대는 진하게 표시하고 지점 색상과 텍스트 범례를 함께 제공한다. 막대는 해당 연도·월 상세 분석으로 연결한다. 그래프 아래에 기준연도·자료 기준일·자동 수집 안내나 월별 수치 접이식 표를 표시하지 않는다. 빠진 달은 축에 유지하며 자료 없는 지점·월을 0원으로 채우지 않는다. 모바일에서는 그래프 내부만 가로 스크롤하고 키보드로도 월별 상세에 접근할 수 있어야 한다. 기존 운영비 상세 화면의 카드와 업무 계산은 유지한다.
- 지점별 상태표는 청구 접수와 연간 인건비 비율·판정을 한 행으로 요약한다. 조회월과 지점 중 가장 오래된 조회일은 공통 안내로 표시하고 운영 기준·개별 조회 시각은 상세 화면에 유지한다. 인건비 판단은 기존 API의 assessment를 따르며 새 계산 기준을 만들지 않는다. 접수 완료된 청구는 과거 재조회 실패 이력만으로 경고 상태에 포함하지 않는다. 실패 이력은 청구 상세 화면에 유지하고 현재 연결 오류는 업무 상태와 별도로 안내한다.
- 지점별 상태표와 상담·무료체험 현황은 같은 행에서 카드 높이를 맞춘다. 고정 높이로 내용을 자르지 않고 더 긴 카드에 맞춰 늘린다. 상담 현황은 상태별 네 가지 건수를 데스크톱·모바일 모두 2행 × 2열로 배치하며, 각 칸은 ‘새 접수 0건’처럼 상태명과 굵은 건수를 한 줄에 표시해 높이를 줄인다. 조회 시각만 덧붙이고 유형별 내역은 신청 관리로 연결한다. 모바일 한 열에서는 각 카드가 내용에 맞는 높이를 갖는다.
- 상담·무료체험 현황은 접근 키 없이 집계 전용 API의 운영 사이트 건수만 표시한다. 실패는 오류 안내를 표시하고 이전 집계는 지운다. 신청자 이름·연락처·메모는 대시보드로 가져오거나 브라우저 저장소에 보관하지 않는다. 상담 신청 관리와 급여 상세도 별도 담당자 접근 키 없이 연다.
- 네이버 광고 추이는 연결 계정의 지점과 실제 수집 기준일을 표시하고 최근 14일 노출수·클릭수를 별도 축의 두 선그래프로 요약한다. 캠페인 합계만 사용하고 소재 합계를 더하지 않는다. 미수집 날짜는 0으로 채우거나 선으로 연결하지 않으며, 저장된 이전 결과·갱신 지연·조회 오류를 구분한다. 일별 수치 표를 키보드·모바일에서도 열 수 있게 제공한다.
- GNB에 ‘기능 찾기’ 버튼을 추가하지 않는다. 키보드 Ctrl/Cmd+K 검색은 유지한다.
- GNB 우측에는 ‘홈페이지’(https://www.thevida.co.kr/)와 ‘관리자’(https://admin.thevida.co.kr/)를 20px 2D 아이콘과 제목으로 표시하고 새 탭으로 연다. GNB의 ‘지식 창고 홈’ 링크는 넣지 않는다. 좁은 화면에서도 제목을 유지하고 필요한 경우 줄을 나눈다.
- 기본 보기는 목록형이다. 사용자가 직접 바꾼 보기와 즐겨찾기 순서는 유지한다.
- 메뉴 아이콘은 현재의 Lucide 2D 라인 SVG를 사용한다. 3D·지점토·이모지·다색 아이콘을 섞지 않는다.
- 본문 카드·목록 제목 앞에는 장식 아이콘을 넣지 않는다. 즐겨찾기는 2D 태그 형태다.
- 제목·설명은 같은 시작 위치에 놓는다. 같은 보기의 카드 높이는 동일하다.
- 상태 메시지는 즐겨찾기 태그 바로 왼쪽에 놓고 수직 중앙을 맞춘다. 연한 배경의 배지, 한 줄 요약, 긴 내용은 말줄임·원문 설명을 사용한다.
- 메뉴·카드에 마우스를 올리면 연한 회색 배경을 표시한다. 선택 상태는 남색 계열 글자와 연한 선택 배경으로 구분한다.
- 새 글 N은 카드와 해당 메뉴에서 같은 읽음 상태를 반영한다. 18×18px 고정 크기이며 줄바꿈·축소되지 않는다. 필터·검색만으로 읽음 처리하지 않는다.
- 모바일에서는 카테고리를 접이식 메뉴로 표시한다. 본문 전체에 가로 스크롤을 만들지 않는다.

## 공통 디자인 토큰

색상과 치수는 아래 값의 복제가 아니라 CSS 변수로 참조한다.

| 용도 | 변수 / 기준 |
| --- | --- |
| 글꼴 | `--ui-font` / Pretendard, Noto Sans KR, system-ui |
| 화면 배경 / 표면 | `--ui-page` / `--ui-surface` |
| 본문 / 보조 글자 | `--ui-text` / `--ui-muted` |
| 주 동작 / 선택 | `--ui-primary` / `--ui-selected` |
| 호버 / 경계선 | `--ui-hover` / `--ui-border` |
| 정상 | `--ui-success`, `--ui-success-bg` |
| 주의 | `--ui-warning`, `--ui-warning-bg` |
| 오류 | `--ui-error`, `--ui-error-bg` |
| 버튼·입력 모서리 | `--ui-control-radius` / 8px |
| 카드 / 상태 배지 모서리 | `--ui-card-radius` / 10px, `--ui-status-radius` / 6px |
| 일반 컨트롤 최소 높이 | `--ui-control-height` / 40px, 터치 환경 44px |
| 본문 최대 폭 | `--ui-content-width` / 1248px |

여백은 기본적으로 4px 배수로 선택한다. 본문 좌우 여백은 데스크톱 24px, 모바일 16px이다. 기존 홈 카드 높이를 맞추는 내부 여백, 아이콘 광학 보정, 출력 문서 치수는 명시적인 예외다.

## 구성요소

### 버튼과 입력

- 새 일반 버튼은 `ui-button`, 주 동작은 `ui-button ui-button--primary`를 사용한다. 한 작업 묶음의 주 동작은 하나를 우선한다.
- 일반 버튼은 흰 표면·얇은 경계선·회색 호버, 주 동작은 공통 남색 계열이다. 데이터의 정상 상태를 의미하는 초록색을 일반 저장 버튼의 브랜드 색상으로 사용하지 않는다.
- 기능별 기존 클래스는 foundation의 호환 선택자로 연결한다. 새 코드는 호환 선택자를 늘리기보다 공통 클래스를 쓴다.
- 탭, 지도 조작, 이미지 미리보기, 텍스트 링크, 삭제 동작은 별도 의미가 있으므로 일반 버튼 규칙을 무조건 덮어쓰지 않는다.
- 입력에는 연결된 label 또는 aria-label이 필요하다. placeholder로 이름을 대신하지 않는다. 모바일 입력 글자는 16px 이상으로 한다.
- 홈 검색창은 큰 입력 높이를 유지하며, 지식 질문 채팅창은 메시지 작성에 맞춘 높이·테두리를 유지한다. 공통 폼 규칙으로 이 두 입력의 구조를 덮어쓰지 않는다.
- 비활성 컨트롤은 시각적으로 약하게 표시하고 클릭할 수 없어야 한다. 진행 중·실패·완료는 텍스트로 설명한다.

### 상태와 피드백

- 기본 상태는 연한 중립색, 정상은 초록, 주의는 호박색, 오류는 빨강을 사용한다. 색만으로 뜻을 전달하지 않는다.
- 새 상태 표시는 `ui-status`와 `data-status="success|warning|error"`를 사용한다. 일반 안내는 data-status를 생략한다.
- 기존 업무 상태의 의미를 바꾸지 않는다. 특히 매출·손익·평판·청구 여부의 데이터 색상은 실제 의미를 보존한다.
- 빈 상태는 이유와 다음 동작을 간단히 설명한다. 로딩·오류·데이터 없음은 서로 다르게 표시한다. 이 문구 원칙으로 사용자가 삭제한 홈 안내를 복원하지 않는다.

### 아이콘과 접근성

- 탐색 아이콘은 20px, 동일한 선 굵기의 Lucide를 사용한다. 컬러는 `currentColor`를 상속한다.
- 장식 아이콘은 `aria-hidden="true"`, 아이콘만 있는 버튼은 실제 동작을 설명하는 접근성 이름을 갖는다.
- 키보드 포커스는 공통 남색 2px 외곽선·3px 간격으로 표시한다. 포커스를 단순히 제거하지 않는다.
- 선택·확장 상태는 aria-pressed, aria-current, aria-expanded 또는 해당 네이티브 요소로 전달한다.
- 텍스트 줄바꿈과 N 배지가 서로 밀거나 겹치지 않아야 한다. 모션 감소 설정을 존중한다.
- 뉴스의 긴 ‘표시 기준’ 안내는 기사 수 옆의 `ui-button ui-info-button`과 `ui-tooltip`으로 접는다. 마우스 호버·키보드 포커스·클릭·터치로 열고, Esc·바깥 클릭으로 닫을 수 있어야 한다. 툴팁 위로 포인터를 옮겨도 읽을 수 있게 유지하고, 모바일 화면 밖으로 넘치지 않게 한다. 인쇄에서는 설명 본문을 보존한다.

## 변경 범위와 예외

- 지도·차트·데이터 표는 정보 의미와 조작 방식을 보존한다. 공통 스타일을 맞추려고 개별 데이터 색상을 일괄 치환하지 않는다.
- 표의 가로 스크롤은 표 전용 컨테이너 안에서 허용한다. 페이지 전체 가로 넘침은 허용하지 않는다.
- 인쇄·PDF·근로계약서 출력과 외부 공유 `support-share.html`은 별도 서식이다. 공통 화면 스타일은 `@media screen`과 내부 페이지 범위에 한정한다.
- 외부 응시 `staff-eval-session.html`은 `ui-standalone` 범위에서 foundation의 토큰·버튼·입력·상태·포커스를 재사용한다. 내부 메뉴는 불러오지 않으며, 모바일 응시 레이아웃은 별도로 유지한다. 음성 실패 시 같은 화면에서 재시도와 글 답변을 제공하고 작성 중인 답변은 보존한다.
- 종사자 평가 목록은 제목·지점 필터를 한 행에, 각 항목의 이름·지점·점수·상태를 한 행에 정렬한다. 좁은 화면에서도 요소를 위아래로 쌓지 않으며 `.eval-list-scroll` 내부에서만 가로 스크롤을 허용한다. 긴 이름은 말줄임과 원문 설명을 제공한다.
- 종사자 평가 상세의 자동 판정은 ‘확인된 내용’과 ‘추가 확인 필요’를 구분한다. ‘빠짐’으로 단정하지 않으며 미응답·건너뜀을 별도 표시한다. 확인된 행동이 두 개 미만이면 순서는 ‘판단 근거 부족’으로 안내하고 기존 저장 결과에도 적용한다. 표시 보완을 위해 저장 점수를 재계산하지 않는다.
- 인증 화면, 잠금 상태, API, 저장 값, 수집기, DOM 식별자, 읽음 처리 로직을 외관 변경 때문에 수정하지 않는다. 사용자 요청에 따라 공통 담당자 접근 키 인증을 전체 업무에서 제거한다. 종사자 평가, 상담·무료체험, 월별 급여·4대보험, 지원사업 준비·기록 및 신청서 초안은 직접 연다. 응시자 본인 확인, 외부 공유 링크 범위·만료, 홈페이지 접수 서버 인증은 별도 기능으로 유지한다.

## 작업·검증 절차

1. 변경 화면과 공통 요소를 확인하고, 이 문서 및 foundation의 기존 컴포넌트를 먼저 찾는다.
2. 현재 사용자 요구를 보존하면서 공통 토큰/컴포넌트에서 수정한다. 다른 페이지까지 영향을 주는 규칙은 선택자 범위를 확인한다.
3. `python -m unittest test_ui_consistency.py`로 전체 내부 페이지의 규칙 연결·공통 스타일 로드·명시적 예외를 확인한다.
4. 변경된 동작에 해당하는 기존 테스트만 실행한다. 스타일 선언을 그대로 베끼는 테스트를 새로 만들지 않는다.
5. 브라우저 검증이 승인된 작업에서는 홈 목록·카드·대표 상세 화면과 320px 모바일 폭을 확인한다. 버튼/입력/상태·키보드 포커스·호버·긴 제목·가로 넘침을 살핀다. 업무 처리 버튼은 시각 검증을 위해 실제 제출하지 않는다.
6. 인증이 필요한 업무 화면을 확인할 수 없으면 접근 가능한 화면과 정적 구조를 검사하고 그 한계를 기록한다.
7. 동의된 배포 범위에 따라 반영하고, 실제 배포 결과를 확인한다. 새 기준이나 의도적인 예외가 생겼다면 문서와 체크를 갱신한다.

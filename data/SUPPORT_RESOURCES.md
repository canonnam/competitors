# 후원·재능기부 데이터

화면은 `data/support_resources.json`만 읽습니다. `assets/*-data.js`처럼 내용을 한 번 더 복사하지 않습니다. 항목을 더할 때는 이 JSON만 고치면 됩니다.

`updated`는 데이터를 반영한 날(`YYYY-MM-DD`)입니다. 아직 반영 전이면 `null`입니다. `items`가 비어 있으면 화면은 빈 상태를 보여 줍니다. 2026-11-03에 수집한 8건이 첫 반영입니다. 확인하지 못한 내용은 지어 넣지 않습니다.

## 항목 필드

| 필드 | 내용 |
| --- | --- |
| `id` | 고유 문자열. 같은 `id`는 한 공고로 병합합니다. |
| `title` | 제목 |
| `org` | 기관 |
| `type` | 유형. 아래 수집 표기를 우선 쓰고, 그보다 더 맞는 유형이 있으면 새 문자열을 써도 됩니다. |
| `summary` | 한두 문장 요약 |
| `target` | 대상. 없으면 빈 문자열 |
| `region` | 지역. 없으면 빈 문자열 |
| `apply_start` | 접수 시작 `YYYY-MM-DD` 또는 `null` |
| `deadline` | 마감 `YYYY-MM-DD`. 상시·원문 미기재·작품별이면 `null` |
| `deadline_note` | 마감 시각, 또는 날짜가 없을 때의 원문 문구. 없으면 `null` |
| `event_date` | 공연일. 시각이 있으면 함께 적습니다. 없으면 생략 |
| `how_to_apply` | 신청 방법 |
| `contact` | 문의 전화·이메일. 없으면 생략 |
| `url` | 원문 http(s) 주소 |
| `collected_date` | 수집일 `YYYY-MM-DD` |
| `sources` | 선택. 같은 공고로 합친 다른 기록. 아래 형식 |

권장 `type`는 수집 표기입니다.

- `무료공연·문화`
- `재능기부`
- `후원품`

다른 문자열이 들어와도 그 유형 필터를 만듭니다.

`sources`의 각 원소는 `id`, `title`, `org`, `url`, `collected_date`만 둡니다. 본 항목과 같은 주소·같은 id는 넣지 않습니다.

형식 예시입니다. 실제 `support_resources.json`에는 넣지 않습니다.

```json
{
  "id": "example-performance",
  "title": "요양원 찾아가는 음악회",
  "org": "지역 문화재단",
  "type": "무료공연·문화프로그램",
  "summary": "요양시설에 무료 공연을 연결하는 신청입니다.",
  "target": "노인요양시설",
  "region": "전국",
  "apply_start": "2026-11-01",
  "deadline": "2026-11-30",
  "deadline_note": null,
  "how_to_apply": "원문 페이지에서 신청서를 제출합니다.",
  "contact": "문의 전화",
  "url": "https://example.com/notice/1",
  "collected_date": "2026-11-03",
  "sources": [
    {
      "id": "example-performance-copy",
      "title": "요양원 찾아가는 음악회",
      "org": "지역 문화재단",
      "url": "https://example.com/notice/1",
      "collected_date": "2026-10-28"
    }
  ]
}
```

## 추가·중복 병합

1. 같은 공고는 한 항목만 둡니다. 다음 중 하나라도 같으면 같은 공고입니다.
   - `id`
   - 원문 URL. `http`/`https`, `www` 유무, 끝 슬래시, 해시, 쿼리 순서만 다른 주소는 같습니다.
   - 기관과 제목. 공백을 한 칸으로 맞추고 영문은 대소문자를 구분하지 않습니다. 기관이나 제목이 비어 있으면 이 조건으로는 합치지 않습니다.
2. 합칠 때는 수집일이 가장 늦은 기록을 본 항목으로 둡니다. 수집일이 같으면 JSON에 먼저 나온 기록을 본 항목으로 둡니다.
3. 본 항목의 빈 제목·기관·유형·요약·대상·지역·신청 방법·문의·공연일·마감 문구·주소·날짜는 다른 기록에 있는 값으로 채웁니다. 이미 있는 값은 덮어쓰지 않습니다. 주소는 http(s) 원문을 우선합니다.
4. 본 항목이 아닌 기록은 `sources`에 남깁니다. 같은 주소와 같은 id가 이미 있으면 다시 넣지 않습니다.
5. 링크가 없거나 `javascript:`처럼 http(s)가 아니면 카드는 새 탭으로 열지 않습니다.

화면은 저장 순서를 그대로 믿지 않고, 위 규칙으로 합친 뒤 수집일 최신순으로 그립니다. 마감일이 오늘보다 이전이면 흐리게 목록 맨 뒤에 둡니다. 마감일이 오늘이면 ‘오늘 마감’이고 아직 열린 항목입니다. 날짜가 있고 `deadline_note`가 있으면 시각처럼 날짜 뒤에 붙입니다. 날짜가 없고 `deadline_note`가 있으면 그 원문만 보여 줍니다. 둘 다 없으면 ‘상시·미정’입니다. `event_date`와 `contact`가 있으면 공연일과 문의로 표시합니다.

## N 표시

N은 수집일 7일이 아니라, 이 브라우저가 아직 확인하지 않은 항목입니다. 기준은 합친 뒤의 항목 `id`이고 `vida-news-seen-v1:support-resources`에 없습니다. 트렌드·뉴스·기관뉴스·평판의 홈 카드와 메뉴와 같은 `assets/news-badge.js` 확인 기록입니다.

사이트 비밀번호는 모든 접속자가 같은 값입니다. 사람별 계정이 없으므로 확인 기록은 서버에 저장하지 않습니다. 브라우저 `localStorage`가 접속자별 저장이며, 한 브라우저에서 확인해도 다른 브라우저의 N은 남습니다.

후원·재능기부 페이지가 화면에 보이게 열린 뒤 목록을 불러오면 그때의 항목을 확인한 것으로 저장합니다. 그 방문의 목록에는 확인 전 항목의 N을 그대로 보여 주고, 다음 방문부터는 빠집니다. 그 사이에 들어온 새 `id`는 다시 N이 됩니다. 숨긴 탭, 홈에서 검색·필터만 한 경우, 불러오기 실패는 확인으로 처리하지 않습니다. 홈 카드와 정책·지원사업 메뉴는 확인 저장이 끝나면 같은 브라우저에서 N이 사라집니다.

트렌드 홈·메뉴 N도 같은 브라우저 확인 정책입니다. 트렌드 카드에는 항목별 N이 없고, 후원·재능기부 목록만 이번 방문에 확인 전인 항목에 N을 붙입니다.
